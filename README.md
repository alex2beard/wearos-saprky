# Sleep Lab / wearos-saprky

Диагностическое приложение Wear OS для проверки ночной записи на Samsung Galaxy Watch4 и новее. Первый целевой прибор — SM-R870 с Wear OS 6 / Android 16.

Версия **0.1.2** записывает через Samsung Health Sensor SDK 1.4.1:

- короткий тест PPG: исходный сигнал зелёного, ИК и красного каналов и их статусы, номинально 100 Гц;
- пульс и интервалы между ударами (IBI), включая статусы качества и пакетную выдачу;
- исходные показания акселерометра, номинально 25 Гц;
- заряд, состояние экрана, режим энергосбережения и временные опорные точки.

Ночная запись использует пульс, IBI и акселерометр. Короткий тест PPG запускается отдельно, без трекеров пульса и акселерометра. Приложение сообщает об ошибках SDK и не подменяет отсутствующий поток другими измерениями. Стадии сна в этой версии ещё не определяются.

На целевом SM-R870 двухминутная запись пульса/IBI и движений дала данные в том числе при выключенном экране. Зелёный PPG в режиме PPG_CONTINUOUS (25 Гц) возвращал нули и при совместном, и при отдельном запуске; причина пока не установлена. Поэтому версия 0.1.2 отдельно проверяет PPG_ON_DEMAND, а ночью использует набор без отдельного PPG-трекера. Доступность нового режима и непрерывность записи за всю ночь ещё нужно проверить на часах.

## Первая проверка

1. Установить APK на часы через Bugjaeger или ADB.
2. Для разработки включить режим разработчика **Health Sensor Service** по [официальной инструкции Samsung](https://developer.samsung.com/health/sensor/guide/developer-mode.html). Он отличается от отладки Android/ADB. На некоторых прошивках сервис называется Health Platform. В интерфейсе Health Platform 1.7.00.05 появление `[Dev mode]` под заголовком означает включение режима; повторная серия из десяти нажатий переключает его обратно. Описание этого варианта интерфейса приведено в [проверке Health Platform 1.7.00.05](https://github.com/LibreStatic/LibreWrist/blob/cfb758549dd4142aa5e8cec12af1bceb75218efa/docs/health-tracking-protocol.md).
3. Запустить **Sleep Lab**, нажать **Пульс + IBI · 2 мин** и предоставить разрешения. Надеть часы, первые 30 секунд оставить экран включённым, затем выключить и дождаться окончания проверки. Это позволяет сравнить получение данных при включённом и выключенном экране. В этом тесте PPG не включается, акселерометр записывается.
4. Кнопка **PPG 100 Гц · 30 с** проверяет три оптических канала через PPG_ON_DEMAND. Надеть часы и оставить приложение открытым все 30 секунд: экран удерживается включённым автоматически. При выходе из приложения или выключении экрана этот тест останавливается. Другие непрерывные трекеры SDK в нём не запускаются. Это соответствует [ограничениям Samsung для on-demand](https://developer.samsung.com/health/sensor/guide/data-specifications.html): только открытое приложение и короткое измерение, без циклического перезапуска для ночной записи.
5. Нажать **Выгрузить ZIP**. Архив появится в `/sdcard/Download/SleepLab/`. Его можно скачать на телефон через Bugjaeger.

Кнопка **Ночная запись** запускает пульс, IBI и движения до 12 часов; отдельный PPG-трекер не включается. Перед ночью зарядить часы. Остановить её можно из приложения или уведомления. При заряде не выше 8% без зарядного устройства или недостатке места запись завершается с сохранением причины. Интерфейс можно закрыть; запись выполняется foreground-службой и не удерживает экран включённым. Автоматическое восстановление после перезагрузки или остановки процесса не выполняется. При прерывании сохранённые файлы доступны для выгрузки; неполный gzip отмечается анализатором.

## Формат записи

ZIP содержит `metadata.json`, `events.csv`, `ppg.csv.gz`, `hr.csv.gz`, `acc.csv.gz`.

В CSV сохранены исходная метка времени Samsung `DataPoint` в миллисекундах, время получения пакета по настенным часам и `elapsedRealtimeNanos`. В PPG после прежних столбцов зелёного канала добавлены `ir_adc,ir_status,red_adc,red_status`; незапрошенные каналы остаются пустыми. Сводка содержит качество каждого канала. Годная строка PPG означает ненулевое значение со статусом 0 хотя бы в одном канале; для подтверждения изменения сигнала сравниваются только годные значения внутри одного канала. Начальные нули и ошибочные выбросы не подтверждают изменение сигнала. Это базовые проверки сигнала, а не проверка точности стадий сна.

Единицы исходного акселерометра не изменены; коэффициент перевода в м/с² указан в метаданных. Пакетные списки IBI сохраняются на том datapoint, на котором их выдал SDK; индивидуальные временные метки ударов не выдумываются. Статусы плохого сигнала, разрешения и состояние датчика ношения сохраняются. Пустые потоки, не запрошенные текущим профилем, не считаются ошибкой.

Для локальной проверки архива:

```bash
python3 tools/inspect_session.py /path/to/sleep-lab-session.zip
```

Анализатор считает частоту по исходным меткам, а не по времени доставки пакетов. Он сообщает пропуски, повторы, обратный ход времени и качество измерений. Сходство с Samsung Health само по себе не доказывает точность классификации стадий сна.

## Сборка

Нужны Linux x86_64, Python 3.10+, Java 17+ и `keytool`. Android Studio и Gradle для этого небольшого Java-проекта не требуются. Помощник скачивает фиксированные официальные Android Build Tools 36, платформу API 36 и Eclipse ECJ 3.40.0, проверяя SHA-256.

Скачать [официальный Samsung Health Sensor SDK 1.4.1](https://developer.samsung.com/health/sensor/overview.html) с собственной учётной записью Samsung и сохранить ZIP или AAR вне репозитория:

```bash
python3 tools/build.py --samsung-sdk /path/to/samsung-health-sensor-sdk-v1.4.1.zip
```

Результат: `dist/sleep-lab-0.1.2-watch.apk` и `dist/build-report.json`. Версия для имени APK и кода приложения берётся из AndroidManifest.xml. Минимальный API — 30, целевой — 36. На Android 16 запрашиваются отдельные разрешения на пульс и дополнительные данные Samsung; на Android 15 и ниже — BODY_SENSORS.

Тесты файловой записи, архивации, формата CSV, пакетных данных и анализа качества запускаются при сборке. Их можно выполнить отдельно:

```bash
python3 tools/build.py --test-only
```

Для разработки создаётся ключ `.local/signing.p12` с alias `sleep-lab`. Пароль по умолчанию — стандартный тестовый `android`, его можно задать переменной `SLEEP_LAB_KEY_PASSWORD`. Сохранять один ключ для последующих обновлений APK; ключ не публиковать в GitHub.

Проверка сборки и подписи APK не заменяет испытаний на физических часах. Первое испытание SDK и записи при выключенном экране выполняется на устройстве владельца.

## Данные и зависимости

Интернет-разрешение отсутствует. Измерения хранятся в приватном каталоге приложения до явной выгрузки выбранной записи в Download. APK не обращается к Sparky, Samsung Health или Health Connect за историей измерений. Удаление приложения удаляет его приватные записи; предварительно выгруженные ZIP остаются в Download.

Исходники проекта распространяются по LICENSE этого репозитория. Библиотека Samsung имеет отдельные условия; AAR, APK, ключи подписи и записи измерений исключены из Git. При сборке из официального ZIP в APK включается предоставленный Samsung Open Source Announcement.

Документация зависимостей: [форматы датчиков](https://developer.samsung.com/health/sensor/guide/data-specifications.html), [разрешения](https://developer.samsung.com/health/sensor/guide/permission-request.html), [пакетная выдача IBI](https://developer.samsung.com/health/sensor/api-reference/com/samsung/android/service/health/tracking/data/ValueKey.HeartRateSet.html).
